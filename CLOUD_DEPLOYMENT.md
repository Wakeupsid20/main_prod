# Static wallet, relay and Neon PostgreSQL
On Cloudflare Pages connect this repository, choose main, set the build command to `npm ci && npm run build:cloud` and output directory to `dist`. Keep the repository root as the project root so Pages discovers functions/api/[[path]].js. Set MAIN_SERVER_ORIGIN to the HTTPS origin of the trusted main server, without a trailing slash. Redeploy after changing it.
  
The browser creates and encrypts credentials and builds proofs. Pages serves public files and relays /api requests to the fixed verifier. The verifier checks proofs, authorizes access and stores registry records in Neon. Keep DATABASE_URL, ZKP_DATA_KEY and ZKP_ADMIN_TOKEN only on the main server. The combined issuer demo still requires the authorized operator to enter their admin token.

Use an existing reachable Veil verifier or the included Render Blueprint (free Docker service, no disk). In Neon select Connect, copy a pooled PostgreSQL connection string, then set DATABASE_URL privately in the verifier environment. Use a dedicated empty database for the demo. Tables are created at startup. This is a fresh registry; existing SQLite records are not migrated. For a previously initialized PostgreSQL registry retain its original ZKP_DATA_KEY. When hosting outside Render set ZKP_PUBLIC_ORIGIN to the verifier HTTPS origin. Test /api/health on the Pages URL after deploying both ends.
